# 安全与发布治理规范：Key-R7

## 文档目的

本文用于验证 MCP Knowledge Builder 在安全边界、鉴权、发布、暂停、删除和权限角色方面的检索与引用能力。本文的核心专有词是 `Key-R7`。如果工具调用检索 `Key-R7`，预期命中本文关于 API Key 生命周期的片段。

## 角色与权限

系统包含三类用户角色：`admin`、`seller` 和 `viewer`。第一个注册用户自动成为管理员。管理员可以管理用户、文档、知识库、MCP 服务和权限。卖家可以上传文档、构建知识库、创建和发布 MCP。查看者主要用于查看和测试，不能执行上传、删除、发布、暂停、恢复、创建密钥等高风险操作。

权限测试时应使用三个账号分别验证。管理员应能修改用户角色；卖家应能完成完整服务构建；查看者应能查看列表和执行允许的测试请求，但上传 Markdown 文件应返回 403。

## API Key 生命周期

`Key-R7` 是本文定义的测试策略名称，不是实际密钥。真实 API Key 必须由系统生成，使用至少 256 位随机值，数据库只保存校验哈希、标识、末尾少量字符和生命周期信息。完整 API Key 只在创建时展示一次；如果用户离开页面后没有保存，只能重新创建新 Key。

外部 MCP 调用必须使用以下请求头：

```text
Authorization: Bearer <api_key>
MCP-Protocol-Version: 2026-07-28
Mcp-Method: tools/call
Content-Type: application/json
```

系统兼容 `Bearer <真实密钥>` 这种带尖括号的输入形式，运行时会剥离尖括号再校验。错误或撤销的 Key 应返回 401。过期 Key 也应返回 401。单个 Key 每分钟请求超过限制时应返回 429。

## 发布治理

发布版本是不可变的。草稿变更不会自动影响线上服务。每次发布会生成新的 Service Revision，并把服务的 `active_revision_id` 切换到新版本。旧版本的资源 URI 中包含旧 revision，如果服务已经重新发布，调用旧 URI 应被视为失效或不可读取，调用方需要重新执行 `resources/list`。

发布失败不能覆盖旧版本。首次发布失败时服务仍应保持未发布。已发布服务再次发布失败时，应继续使用旧的 active revision。测试时可以通过非法工具名称、重复工具名称、未声明 Prompt 变量或 Prompt 依赖缺失构造失败场景。

## 暂停、恢复与删除

暂停服务后，真实 `/mcp/{service_id}` 调用应返回 503，错误信息应包含“服务已暂停”。恢复服务后，原服务地址和未撤销、未过期的 API Key 可以继续使用。

删除 MCP 服务会删除服务、服务版本、API Key 和调用日志，但不会删除原始文档和知识库。服务删除后，原 API Key 再调用该服务应返回 401 或服务不可用错误。删除服务之后，如果相关文档和知识库不再被其他 MCP 使用，它们应允许删除。

## 敏感信息要求

任何错误响应都不应包含服务器磁盘路径、Python 堆栈、数据库连接字符串、API Key 明文或环境变量。`get_document`、`list_documents` 和 `resources/list` 也不应返回本地文件系统路径，只能返回文档 ID、标题、文件名、大小、哈希、行号、偏移量和 URI。
