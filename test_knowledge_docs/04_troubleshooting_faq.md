# 故障排查与 FAQ：NoTrain-01

## 文档目的

本文用于验证 FAQ 搜索、术语解释、结构化报告、证据提取和对比类 Prompt 的输入效果。本文的核心专有词是 `NoTrain-01`。检索该词应命中“是否会训练模型”章节。

## 是否会训练模型？

不会。`NoTrain-01` 表示 MCP Knowledge Builder 只提供知识访问能力，不训练模型，也不调用模型生成最终答案。系统返回的是 Markdown 原文片段、文档正文区间、资源内容或 Prompt 消息模板。真正的自然语言回答由外部模型客户端完成。

## 为什么搜索没有结果？

如果搜索没有结果，首先确认查询词是否出现在绑定知识库版本中。MVP 使用全文检索和中文 n-gram 处理，不承诺理解同义改写。如果用户用“自动摘要”检索，但文档里只写“生成总结”，可能没有命中。测试时应优先使用文档中明确存在的词，例如“青松路由”“Key-R7”“EchoBridge-stdio”。

其次确认服务是否绑定了正确的知识库版本。上传新文件后，如果没有重新构建知识库并重新发布服务，线上 MCP 仍然读取旧版本。草稿测试只能验证候选配置，不能代表真实 `/mcp/{service_id}` 已经更新。

## Resources 和 Tools 有什么区别？

Resources 控制资源列表和资源读取的暴露范围。Tools 读取的是服务绑定知识库版本内的资料，两者不是同一个权限开关。只开放 A 文档为 Resource 时，`resources/list` 只应显示 A 的片段；但如果绑定知识库还包含 B 文档，`search_knowledge` 仍可能搜索到 B。

## 为什么 get_document 需要 document_id？

`get_document` 是一个只读工具，用于读取授权文档的正文区间。它不接收文件路径，也不读取任意 URL。调用者必须先通过 `list_documents`、`search_knowledge` 命中结果或资源目录拿到有效的 `document_id`，再传入 `offset` 和 `limit` 读取正文。`offset` 和 `limit` 以规范化正文字符计数，返回 `has_more` 和 `next_offset` 支持续读。

## 常见错误

| 错误现象 | 可能原因 | 预期处理 |
| --- | --- | --- |
| 401 | 缺少 Bearer API Key、Key 无效、Key 已撤销或过期 | 创建新 Key 并重试 |
| 400 | 协议版本错误、请求头方法与 body 方法不一致、参数非法 | 修正请求结构 |
| 404 | 未知工具、未知 Prompt、资源 URI 失效或未开放 | 刷新能力列表或资源列表 |
| 429 | 单 Key 请求频率过高 | 降低频率后重试 |
| 503 | 服务已暂停 | 恢复服务后重试 |
