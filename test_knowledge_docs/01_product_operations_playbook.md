# 产品运营手册：青松路由知识服务

## 文档目的

本文用于构建 MCP Knowledge Builder 的正向测试知识库。内容模拟一个卖家端知识服务产品从资料准备、知识库构建、MCP 发布到外部调用的完整运营流程。文档包含多个可检索关键词、跨章节逻辑、表格、列表和长段落，方便验证 Markdown 切片、中文检索、英文术语检索、行号引用和文档读取续页。

本文的核心专有词是“青松路由”。如果测试服务的 `search_knowledge` 工具用关键词“青松路由”检索，预期应优先命中本文的“核心能力”和“发布前检查”相关片段。

## 业务背景

青松路由是一套面向本地 Markdown 资料的只读知识服务方案。运营人员把产品说明、常见问题、发布规范和接入指南整理为 Markdown 文档，上传到 MCP Knowledge Builder，构建为不可变知识库版本，然后把该版本发布为支持 Tools、Resources 和 Prompts 的 MCP 服务。

系统不训练模型，也不直接替用户生成最终答案。它的职责是提供可控、可追溯、可测试的知识访问能力。外部模型应用通过 MCP 方法发现能力、调用工具、读取资源或获取提示词模板，再由模型根据返回内容组织答案。

## 核心能力

青松路由的第一项能力是资料冻结。文档上传后会按规范化正文生成内容哈希，知识库构建时会记录每份文档的 `document_id`、标题、文件名、大小和内容哈希。服务发布时绑定的是某个明确的知识库版本，因此后续上传新文件或修改知识库草稿，都不会改变已经发布的服务结果。

青松路由的第二项能力是能力配置。运营人员可以为一个服务启用不同类型的 MCP 能力：Tools 用于主动调用，比如搜索知识库或读取文档；Resources 用于把文档目录和文档片段暴露为 URI；Prompts 用于提供带参数的消息模板。三类能力彼此独立，启用 Prompt 不代表模型一定调用工具，启用 Resource 也不代表内容自动进入模型上下文。

青松路由的第三项能力是安全边界。外部调用必须携带服务级 Bearer API Key。API Key 绑定到具体服务，不能跨服务读取资料。运行时根据 `service_id` 和当前发布版本确定可访问范围，不允许调用者传入任意磁盘路径、知识库 ID、URL 或 SQL。

## 构建流程

1. 注册并登录工作台，第一个账号自动成为管理员。
2. 上传 UTF-8 Markdown 文件，扩展名必须是 `.md` 或 `.markdown`。
3. 在文档库中选择资料，创建知识库并执行构建。
4. 试检索关键词，例如“青松路由”“资料冻结”“能力配置”。
5. 创建 MCP 服务，绑定一个可用知识库版本。
6. 配置工具、资源和提示词。
7. 使用草稿测试验证 `server/discover`、`tools/list`、`resources/templates/list` 和 `prompts/list`。
8. 发布不可变 MCP 服务，创建 API Key，并在调用控制台执行真实 `/mcp/{service_id}` 请求。

## 发布前检查

发布前需要确认服务至少启用一种能力。如果 Tools、Resources 和 Prompts 全部为空，发布应失败。还需要确认公开名称符合规则：以小写字母开头，只包含小写字母、数字和下划线，总长度不超过 64 字符。同一能力类别中不能出现重复名称。

发布前还应检查资源范围。假设本服务只开放“产品运营手册”和“安全发布规范”两份文档的资源，那么 `resources/list` 不应返回未勾选文档的片段 URI。需要注意，资源范围只控制 Resources 暴露范围，不限制工具搜索整个绑定知识库。要让某份资料完全不被工具搜到，应把它从绑定知识库版本中移除。

## 可观测性

运营人员应记录每次测试的服务 ID、发布版本、知识库版本、API Key 后六位、调用方法、耗时和结果状态。系统会保存基础调用日志，日志用于诊断方法是否被调用、API Key 是否过期、服务是否已暂停、响应体是否超过限制。

## 操作风险

如果用户把内部资料误加入产品服务绑定的知识库，即使没有把内部资料勾选为 Resource，`search_knowledge` 和 `get_document` 仍可能读取它。正确做法是建立更小范围的知识库版本，然后重新发布服务。暂停服务只能阻止新的外部调用，不能收回已经返回给客户端的内容。
